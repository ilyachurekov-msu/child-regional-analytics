# Запуск и автоматическая приёмка

Docker Desktop на компьютере пользователя не требуется для проверок. Workflow `.github/workflows/acceptance.yml` выполняется на GitHub-hosted Ubuntu при каждом PR и отправке ветки codex/mvp-acceptance. Jobs: unit/Ruff/синтаксис/контракты; PostgreSQL 16+pgvector; Docker+API+Streamlit+Chromium; сканирование секретов и зависимостей. У обязательных шагов нет continue-on-error, PostgreSQL-тесты не skip при недоступной БД. Их невозможно заменить SQLite.

Тестовая PostgreSQL принимает только имя базы regional_ci_test. Установленный TEST_DATABASE_URL обязателен для `pytest -m postgres tests/integration`. Docker-job использует отдельный disposable volume, сохраняет логи, скриншоты и JUnit в артефакты и удаляет только свой CI-том при завершении. Перезапуск сервиса db проверяет сохранение данных. Искусственные CI-значения имеют отдельный источник SYNTHETIC CI ONLY и не загружаются в пользовательскую БД.

Проверка реального источника вынесена в ручной workflow Controlled source check (`workflow_dispatch`), расписания нет. Он не вызывается на PR, не публикует исходники и не разворачивает сервер; архивируется лишь отчёт. Периодическое обновление можно включить позже, добавив согласованное расписание и контроль доступности; сейчас оно не активно.

Для разработчика без Docker Desktop можно использовать отдельно установленный PostgreSQL 16 и Python по README. Для пользователя без локальной БД: просматривать успешность Actions и скачивать артефакты проверок; это ещё не размещённое приложение. Рабочий сервер/публичная публикация не создавались. GitHub Actions не является постоянным сервером или рабочей БД: CI-том и его статистика удаляются в конце job.

После подтверждения CI для локального приложения используется инструкция README. Интерфейс на 8501, Swagger на 8000/api/v1/docs, PostgreSQL-порт наружу не открывается. Остановить Compose можно без -v, сохранив рабочую статистику. Пароль задаётся в .env; файл игнорируется Git. Новые миграции применяются `alembic upgrade head`, существующие производственные таблицы не удаляются.
