# Контролируемые обновления

`python -m scripts.update_data --source kemerovo-yearbook-2022 --dry-run` получает разрешенный известный источник, сохраняет оригинал вне Git, проверяет формат/размер, SHA, структуру, годы, единицы и контрольные соотношения. `--file` позволяет воспроизвести проверку по сохраненному оригиналу. Dry-run не открывает БД и не меняет наблюдения. Это техническая возможность оператора, не требование пользовательской ручной загрузки.

При одинаковом SHA и версии адаптера источник отмечается unchanged. Измененный файл проходит строгий адаптер, затем транзакционный ETL с существующей историей ревизий. Ошибка batch/качества теперь вызывает исключение **внутри** transaction context: рабочие данные откатываются до commit. Каждый запуск получает UUID и отчет data/archive/update-<UUID>.json, последний отчет отдельно. State/checksum обновляется только после успешной загрузки. Архив, state и отчеты не публикуются в Git.

`python -m scripts.update_worker` — отдельный минимальный локальный процесс. По умолчанию STAT_UPDATES_ENABLED=false. Для включения задайте true и STAT_UPDATE_INTERVAL в секундах (минимум 3600, по умолчанию 86400); обрабатываются только enabled источники manifest. Рабочая PostgreSQL должна иметь постоянное операторское хранилище. GitHub Actions используется для воспроизводимых тестов, не для постоянной БД; автоматическое расписание Actions не включается.

TLS, сертификаты и ограничения доступа не обходятся. Изменение неизвестной структуры останавливает загрузку. Адаптеры централизованных изданий еще не утверждены: не подключайте произвольный файл под видом проверенного. Источник без подтвержденной даты публикации хранит NULL, дата получения фиксируется отдельно в provenance/отчете и Batch.loaded_at.

Для будущего контейнерного запуска необязательный сервис updates находится в Compose profile updates: после явного STAT_UPDATES_ENABLED=true запускать `docker compose --profile updates up -d updates`. По умолчанию профиль выключен; обычный запуск/CI не выполняет сетевые статистические обновления. .env читается через общий Pydantic Settings, включая флаг и интервал.
